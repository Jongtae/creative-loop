# 구조와 구현 선택

## 배포 단위

하나의 FastAPI 프로세스가 정적 웹 화면과 JSON API를 제공한다. SQLite와 로컬 파일 저장소를 사용한다. 프런트엔드는 외부 CDN이 없는 HTML/CSS/JavaScript이며 별도 Node 빌드가 필요 없다. 디자인 생성·특징 계산은 Python, 렌더링 산출물은 SVG다.

```
허가받은 이미지 / 관측 JSON·CSV
          ↓
입력 검증 · 목적별 사용권 · 기본 개인정보 최소화
          ↓
SQLite [assets, observations, batches, designs, revisions, preferences, provider_calls]
          ↓
픽셀 특징 + 비교 가능한 관측 그룹
          ↓
브리프 → 레이아웃 후보 생성 → SVG → 편집 / A·B 선택 → SVG·PNG·JSON·ZIP
          ↑                           ↓
선택적 외부 AI 이미지·교정·비전     개인 디자이너 선택 모델
```

## 모듈

| 파일 | 책임 |
|---|---|
| `models.py` | 입력 제한, 색/레이아웃 스키마, 시간·권한 검증 |
| `store.py` | 연결 단위 트랜잭션, WAL, 데이터 읽기·저장 |
| `features.py` | 이미지 특징, 이벤트 빈도, 근거 검색, 기술 점검·개인 선택 모델 |
| `design.py` | 재현 가능한 생성 파라미터, 한국어 줄바꿈·SVG 렌더링 |
| `providers.py` | 외부 AI API 계약, 동의 이후 호출, 한도·오류 처리 |
| `app.py` | API, 로컬 보안 경계, 편집 버전, ZIP 내보내기 |
| `static/` | 브리프 / 작업실 / 편집기 / 레퍼런스 DB / 이력 |
| `scripts/watch_imports.py` | 로컬 파일 증분 가져오기 |

## 데이터 모델

`assets`: ID, 해시, 픽셀/의미 특징 JSON, 권한 JSON, 생성 시각. 이미지는 ID 기반 로컬 PNG 파일이다. AI 생성물에는 모델·작업 종류·프롬프트·원본 asset ID를 기록한다. 프롬프트도 민감 데이터일 수 있으므로 로컬 저장소를 보호해야 한다.

`observations`: 원본 플랫폼/콘텐츠 ID, 관측 시각, 데이터 JSON. 동일 `(platform, source_id, observed_at)`는 중복 저장하지 않는다. 기존 스냅샷을 새 값으로 덮어쓰는 구조가 아니다.

`batches`: 브리프, 관측 그룹 조건, 난수 seed, 생성 수. `designs`: 편집 가능한 brief/spec, 엔진 버전, 참고 관측 ID, 현재 revision, 최종 후보 선택 여부. `revisions`: 변경 전 스냅샷. `preferences`: 승자/패자, 당시 특징과 revision, 선택 이유. `provider_calls`: 모델·상태·usage 메타데이터; API 키는 저장하지 않는다.

## 기본 시안 생성

6 layouts × palette roles × 3 motifs × font scale의 조합을 재현 가능한 순서로 탐색한다. 최초 후보에는 레이아웃을 분산 배치하고 이후 조합을 추가한다. 최대 60개로 제한한다. 최초 스펙 생성에는 대비가 높은 본문색을 사용한다. 브리프와 seed가 같고 참고 데이터가 같으면 기본 파라미터는 재현된다. 외부 AI 생성 이미지의 재현성은 보장하지 않는다.

글자·벡터 그래픽은 SVG 요소로 남기며 입력 이미지는 별도 영역에 임베드한다. 이미지 자체는 래스터이며, 내부 피사체나 AI가 그린 글자가 편집 가능한 레이어가 되는 것은 아니다. 폰트는 운영체제의 sans-serif 계열을 이용한다. 장문은 추정 문자 폭으로 줄바꿈·축소하므로 전문 조판 검증을 대체하지 않는다.

## 관측치를 생성에 사용하는 현재 방식

사용자가 출처를 지정하고 `use_evidence`를 켠 경우만 적용한다. 같은 카테고리, 유입 구분, 관측 창, 최근 기간, 동일 노출 기준, 동일하게 수집된 이벤트 항목 집합으로 묶는다. 데모는 제외한다. 출처별 가장 최근 스냅샷만 사용한다. 그룹이 여러 개면 가장 큰 그룹을 선택한다.

생성 활용이 허용된 실제 사례 3개 이상일 때, 관측 이벤트 빈도가 높은 사례에 기록된 레이아웃을 생성 후보 순서에 참고한다. 이 최소 수는 제품 휴리스틱이지 통계적 유의성 기준이 아니다. 색상·콘텐츠 의미·댓글 감정을 학습해 새로운 크리에이티브 성과를 최적화하는 모델은 아직 없다.

## 참여 지표와 근거 검색

각 이벤트를 `횟수 / 노출수 × 1000`으로 표시한다. 노출수가 없을 때만 조회수를 쓰고, 둘을 같은 그룹에 섞지 않는다. 분모가 없으면 비율을 만들지 않는다. 동일한 사람이 여러 이벤트를 일으킬 수 있으므로 결과는 선호 확률이 아니다.

생성 참고용 순서는 같은 항목 집합의 이벤트 합을 사용하고, 그룹 중앙값을 1,000회 가상 노출의 사전값으로 둔 평활을 적용한다. 1,000은 미리 정한 값이며 데이터로 최적화한 인과 모형이 아니다. 이벤트 종류별 의미 차이·게시자 규모·광고 예산·노출 알고리즘·뉴스 효과는 여전히 남는다.

유사 근거는 `0.55 × 강조색 RGB 근접도 + 0.45 × 레이아웃 일치`로 찾는다. 이는 CLIP 같은 의미 임베딩 검색이 아니다. 상위 3개와 실제 댓글 최대 4개를 보여준다. 댓글 감성 분석이나 인물 프로파일링은 수행하지 않는다.

## 시안 점검과 개인 선택 정렬

기본 점검 = `0.6 × 대비 점검 + 0.4 × 배경·강조의 브랜드 팔레트 일치`.
대비 점검은 `min(대비율 / 7, 1) × 100`이다. 본문/배경의 4.5:1 미만은 내부 경고이며 화면 전체의 WCAG 적합성 인증이 아니다. 이미지 위 텍스트·로고·브라우저 렌더링을 모두 평가하지 않는다.

같은 카테고리에서 서로 다른 6쌍 이상 선택하면, 승자/패자 특징 차이로 L2 정규화 쌍대 로지스틱 모델을 적합한다. 같은 시안 쌍의 반복 선택은 최신 선택 한 번으로 처리한다. 6쌍 기준은 조기 피드백 기능을 위한 장치이며 예측 성능이 검증됐다는 뜻이 아니다.

정렬에 `0.75 × 기본 점검 + 0.25 × 개인 선택 지수`를 쓴다. 모델은 소비자 반응이 아니라 **이 로컬 작업자의 선택 경향**을 설명한다. 아직 사용자 ID·다중 사용자 분리·홀드아웃 평가가 없다. 고객 선호 예측 필드는 항상 `null`이다.

## API 개요

| 경로 | 작업 |
|---|---|
| `GET /api/health` | 로컬 상태, 수량, 설정된 기능 |
| `POST/GET /api/assets` | 이미지 추가·목록 |
| `GET /api/assets/{id}/image`, `DELETE /api/assets/{id}` | 이미지 조회·자산 삭제 |
| `POST /api/observations/import`, `/import-file` | JSON 배열 또는 파일 입력 |
| `GET /api/observations`, `DELETE /api/observations/{id}` | 관측 조회·삭제 |
| `POST/GET /api/batches` | 생성·작업 이력 |
| `GET /api/batches/{id}/designs`, `/export` | 시안 목록·ZIP |
| `DELETE /api/batches/{id}` | 시안·편집 이력·연결 선택 삭제 |
| `GET/PUT /api/designs/{id}` | 조회·버전 확인 편집 |
| `GET /api/designs/{id}/svg`, `/revisions` | 산출물·변경 전 이력 |
| `POST /api/designs/{id}/fix-contrast`, `/select` | 대비 교정·후보 토글 |
| `POST /api/preferences` | 같은 배치 두 시안의 선택 |
| `POST /api/ai/art-direction`, `/vision`, `/images` | 선택적 유료 AI |

정확한 기계 판독 스키마는 `/openapi.json`에 있다. `/docs` CDN 기반 화면은 제공하지 않는다. 모든 쓰기에 `X-Creative-Loop: 1`이 필요하다. APP_TOKEN을 설정한 경우 API마다 Bearer 토큰이 필요하다.

## 확장 전 필요한 작업

실사용 데이터 규모에 맞춘 SQL 조회·페이지네이션과 스키마 마이그레이션, 작업 큐, 서버 단위 비용 제한, 사용자 인증·인가, 클라우드 저장소 수명주기, 모델 버전/홀드아웃 평가를 분리한다. 현재 조회 경로는 관측 최대 10,000개, 일부 시안 조회 최대 500개를 전제로 한 로컬 MVP이며 전량 수집 시스템의 운영 구조가 아니다.
