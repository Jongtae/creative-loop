# 크리에이티브·반응 데이터 계약

## 수집 전제

데이터 사용자는 수집·분석·생성 참고·외부 모델 입력 각각의 근거를 확인해야 한다. 공개 게시물이라는 이유만으로 모든 목적의 이용이 허용된다고 간주하지 않는다. 이 앱은 플랫폼 약관을 자동 검사하거나 사용권을 법적으로 확정하지 않는다. 허가받은 자사 채널·직접 조사·계약된 제공자의 내보내기부터 연결한다.

## 관측 JSON 예시

아래 숫자는 **형식 설명용**이다. 실데이터로 저장하려면 실제 값·사용권·시각을 넣는다. 첨부 데모 파일의 `is_demo`를 지워 실데이터처럼 쓰지 않는다.

```json
{
  "source_id": "campaign-post-001",
  "platform": "owned",
  "source_url": "https://example.com/authorized-post",
  "title": "자사 크리에이티브 제목",
  "category": "lifestyle",
  "traffic": "organic",
  "media_type": "image",
  "window_hours": 168,
  "published_at": "2026-10-01T10:00:00+09:00",
  "observed_at": "2026-10-08T10:00:00+09:00",
  "impressions": 10000,
  "views": null,
  "likes": 120,
  "shares": 14,
  "comments_count": 9,
  "saves": null,
  "comments": ["개인정보를 제거한 실제 댓글 발췌"],
  "asset_id": null,
  "palette": ["#F6F1E8", "#EE5A36"],
  "layout": "editorial",
  "rights_basis": "실제로 확인한 사용권 근거",
  "allow_analysis": true,
  "allow_generation": false,
  "allow_model_input": false,
  "is_demo": false
}
```

API에는 위 객체를 배열로 전달하거나 `{"observations": [...]}`로 감싼다. 파일 입력은 JSON 또는 UTF-8 CSV를 지원한다. `examples/`는 같은 계약의 합성 데모다. 노출수·조회수의 확인된 값은 양수여야 하며, 노출 0인 게시물은 아직 비교에 적합하지 않으므로 분모를 비워 둔다. 댓글 등 이벤트는 0과 미수집을 구분한다.

CSV의 `palette`, `comments`, `tags`는 JSON 배열 문자열을 사용한다. 불리언은 `true`/`false`, 미수집 숫자는 빈 칸이다. CSV 수작업 편집보다 앱 폼 또는 JSON을 권장한다.

## 이미지 연결

먼저 `/api/assets`로 이미지를 올리고 응답 ID를 `asset_id`에 넣는다. 연결된 이미지의 픽셀 특징을 관측 스냅샷에 함께 저장한다. `palette`를 생략하면 자동 추출 색을 쓴다. 레이아웃은 원래부터 정답을 알고 있으면 직접 입력하고, AI 분석의 제안은 확인 후 기록한다. 이미지 의미 분석이 레이아웃 태그나 고객 선호 레이블을 자동으로 확정하지는 않는다.

기본 업로드는 분석을 위한 표준화를 위해 EXIF를 제거하고 PNG로 저장한다. 최대 2048px로 축소하며 **투명 영역은 흰색으로 합성**한다. 원본 보존·투명 로고 제작이 필요한 워크플로는 별도 원본 저장 계층이 필요하다. 업로드 파일 한도는 10MB/2천만 화소이고, GIF·동영상·다중 프레임은 받지 않는다.

## 시각·표본의 의미

게시 시각과 관측 시각은 시간대를 포함해야 하며 미래 관측은 거부한다. `window_hours`는 사용자가 선언한 측정 창이다. 서버는 그 창에 해당하는 지표가 실제로 정확히 집계됐는지 검증하지 않는다. 서로 다른 기간의 누적 지표에 같은 창을 붙이면 비교가 왜곡되므로 공급 시스템이 이를 보장해야 한다.

동일 시점의 같은 게시물은 중복 처리한다. 새로운 스냅샷은 새 `observed_at`으로 추가한다. 실제 비교에는 해당 조건의 최신 스냅샷만 쓰되 원본 이력은 유지한다. 채널/작성자 식별 정보는 최소화하고, 개인별 민감 특성·신원 정보를 넣지 않는다.

## 삭제와 잔존 데이터

관측 삭제는 해당 관측 스냅샷과 댓글을 삭제하지만 독립 자산 이미지는 삭제하지 않는다. 배치 삭제는 그 배치의 시안·버전·선택 기록을 삭제한다. 자산이 관측·시안·이전 버전에 사용 중이면 이미지 삭제를 거부한다. 관련 관측과 배치를 먼저 제거해야 한다.

이미 내보낸 SVG/PNG/ZIP이나 사용자가 만든 백업, 외부 서비스에 전송한 데이터는 이 앱의 삭제로 회수되지 않는다. 법적 삭제 요청과 플랫폼 보존 정책은 운영 절차로 별도 관리해야 한다.
