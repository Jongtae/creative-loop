# 연구 원문 → 제품 구현

## 출발 문서

사용자가 이번 프로젝트의 시작점으로 지목한 조사 문서를 Library에서 찾아 전체 텍스트를 확인하고 추출본을 보존했다.

| 로컬 사본 | 원문 이름 | 원문 파일 ID | 형식 |
|---|---|---|---|
| `research/source-01.txt` | Executive Summary(1) | `file_00000000c0dc81f78cd85cc916e99faa` | Deep Research 추출 텍스트 |
| `research/source-02.txt` | 요약(2) | `file_00000000a0e081f7b2cef5ec8e5cdc0d` | Deep Research 추출 텍스트 |

원문은 변경하지 않았다. 텍스트의 인용 표시는 원문 보고서 내부 표기이며, 이 저장소에서 모든 링크·출처·성능·정책을 다시 검증했다는 뜻은 아니다. 원본 서비스의 보고서 UI나 첨부 이미지를 복제한 것은 아니다.

## 제품 방향의 우선순위

사용자의 명시적 목표는 ‘리서치/페르소나’가 아닌 **실제 제작·교정·대량 시안 탐색·선택**이다. 따라서 보고서의 페르소나 챗봇·점수 보고서·장기 데이터 수집 선행 중심 제안을 그대로 제품 명세로 삼지 않았다.

| 원문 제안 | 구현 결정 | 이유 |
|---|---|---|
| 크리에이티브와 반응 DB | 채택: 이미지/특징/반응/시각/권한 연결 | 디자인 대상과 그 반응을 분리하지 않기 위해 |
| 먼저 광범위한 SNS 수집 | 축소: 수동·파일 가져오기와 폴더 워처 | 미확보 데이터/API 권한을 가정하지 않기 위해 |
| 색/형태/의미 특징 | 픽셀 특징 기본, 비전 어댑터 선택 | 외부 호출 없이 작동하고 비용·검증 경계를 명확히 하기 위해 |
| 페르소나와 가상 고객 평가 | MVP 제외 | 실제 선호와 합성 응답을 혼동하지 않기 위해 |
| 생성 모델 파인튜닝 | 보류 | 이용 허가된 학습 데이터와 성능 평가가 먼저 필요 |
| 실무 제작 UI | 우선 구현 | 프로젝트의 핵심 사용자 가치 |
| 인간 선택 피드백 | 작은 쌍대 개인 선택 모델로 구현 | 실제로 선택된 시안과 그 이유를 보존하기 위해 |
| 브랜드 정합성·다양성·성과 최적화 | 대비/팔레트 점검 + 여러 레이아웃, 성과 예측 제외 | 점검 규칙과 실증된 선호 모델을 분리하기 위해 |
| 실사용 실험 | 백로그의 인수 기준으로 유지 | 모델/제품 효과를 입증하려면 별도 실험 필요 |

## 원문을 그대로 사실로 채택하지 않은 부분

두 문서에는 동일 모델의 라이선스 표기가 서로 다르거나, 정확도 수치·API 무료 이용·플랫폼 접근 범위가 현재 구현에서 확인되지 않은 부분이 있다. 이를 근거로 라이선스 허용이나 전량 수집 가능성을 주장하지 않는다. 특히 객체 인식·분할 모델을 실제 의존성으로 추가하기 전 **해당 저장소의 라이선스, 선택한 가중치의 라이선스, 사용 목적**을 별도로 확인해야 한다.

보고서에서 언급한 샘플 수·개발 기간·성능은 계획 예시 또는 원문 주장이지, 이번 프로젝트의 측정 결과가 아니다. 합성 에이전트의 수는 인간 표본 수가 아니다. 단순 익명화/해시 처리를 개인정보 법적 문제의 완전한 해결책으로 취급하지 않는다.

## 구축 vs 연동

**직접 구현:** 크리에이티브·관측·권한의 데이터 계약, 편집 가능한 DesignSpec, 생성/교정 UI, 시안 이력, 개인 선택 기록, 출처 연결과 평가 경계.

**검증된 라이브러리 활용:** FastAPI/Pydantic 입력·API, Pillow 이미지 표준화, NumPy 계산, SQLite 저장, HTTPX API 클라이언트, Playwright 테스트.

**외부 서비스 어댑터:** OpenAI Responses(브리프·비전), Image API(이미지 생성·편집). 계약 테스트만 수행했으며 실호출·품질·비용은 파일럿에서 확인한다.

**다음 조사·연동 후보:** 의미 검색용 이미지 임베딩, 전문 레이아웃·폰트 특징 추출, 로컬 생성 모델 서빙, Figma 네이티브 레이어/디자인 시스템 연결, 승인된 소셜 API 한 개. 원문 목록에 있다는 이유만으로 모두 설치하거나 추천 확정하지 않는다.

## 참고 순서

1. 실제 제작 경로와 에러 처리 완성.
2. 허가받은 이미지/반응 자료로 계약 검증.
3. 실제 API 계정에서 이미지·편집 기능 파일럿.
4. 수집원 1개와 갱신/삭제 운영 연결.
5. 인간 선택과 실제 성과의 별도 홀드아웃 평가.
