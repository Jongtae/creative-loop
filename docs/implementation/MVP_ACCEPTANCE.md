# MVP 목표·테스트·합격 판정

plan-v1.2 / 2026-10-17. 수치는 **제안하는 제품 인수 기준**이며 측정된 성능이나 통계적 충분성 보장이 아니다. 설계 PR 검토에서 기본값을 확정하고 실제 파일럿 전에 protocol/manifest hash로 동결한다. 결과를 본 뒤 기준·분모·제외 규칙을 낮춰 합격시키지 않는다.

## 제품 목표

디자이너가 브랜드 브리프를 입력하고, 사용권 있는 최근 크리에이티브·실제 반응을 참고해 여러 콘셉트와 이미지를 만들며, 편집 가능한 디자인으로 조합·교정·비교하여 실제 사용할 파일을 내보낸다. 선택과 실제 게시 결과를 다음 제작의 근거로 남긴다.

리서치 리포트, 페르소나 대화, 예쁜 데모 화면만으로는 합격하지 않는다. 반응 DB는 제작 입력이며 출력은 실제 디자인이다.

## 완료 수준과 범위

| 수준 | 필요한 증거 | 표시할 상태 |
|---|---|---|
| L0 | 기존 main의 로컬 MVP·기존 CI | 로컬 프로토타입 |
| L1 | 필수 코드·계약·보안·회귀·장애·mock E2E 통과 | 기술 검증 후보, 외부/품질 미검증 구분 |
| L2 | L1+승인된 실제 소스+실제 AI+사람 품질/사용성+설치·복구+소유자 승인 | 실사용 제작 MVP |
| L3 | 별도 홀드아웃/실제 실험으로 학습·성과 개선 검증 | 입증된 대상·범위에 한해서 개선 주장 |

**필수 목표는 L2다.** 단일 디자이너, 한국어/영어 정지 이미지, 로컬 또는 접근 제한 환경이다. 선택 확장 CL-050 Figma/CL-051 ComfyUI/CL-058 실제 트래픽 실험은 미활성 상태를 명시하면 L2를 막지 않는다. 모든 SNS 전량 수집, 개인 프로파일링, 동영상 타임라인, 광고 자동 집행, 다중 테넌트 SaaS, 기초 이미지 모델 훈련은 별도 범위다.

## L2 수직 시나리오

브랜드 저장 → 허가된 실제 레퍼런스·반응 연결 → 특징/근거 선택 → 콘셉트 호출 견적·승인 → 3개 콘셉트 → 이미지 호출 견적·승인 → 콘셉트별2장 → 최대60개 레이아웃 → 텍스트/배치/로고/마스크 교정 → 규칙·사실 검토 → 비교/선택 → 같은 revision 내보내기 → 게시 결과 수동 연결 → 다음 제작에 참고.

실제6장은 첫 live 검증량이다. 코드 상한은 콘셉트1..6×이미지1..4, 전체 독립 이미지24장, 레이아웃60개다. 기본은 소량3장. 60개 레이아웃을 60개 AI 이미지로 표시하지 않는다. 실패를 fake 결과로 대체하지 않는다.

## 실제 사람 품질 평가

5과제는 제품 소개, 프로모션, 브랜드 메시지, 정보 카드, 기존 이미지 교정이다. 권한 있는 브랜드 또는 명시된 가상 브랜드를 사용하되 실제 디자이너가 수행하고 평가한다. 없는 할인·효능·추천사는 생성 금지.

실제 디자이너2명(소유자 포함)이 가능한 범위에서 생성 방식명을 숨긴 결과를 무작위 순서로 평가한다. 각1..5점은 브랜드 적합, 위계/가독성, 시각 완성도, 브리프·사실 충실성, 수정 용이성이다. 사용 가능한 안은 **두 평가자의 전체 항목 평균≥4.0, 각 항목의 평가자 평균≥3.0**, 중대한 사실/필수 로고/문구/권한 오류0이다. 불일치와 실패안도 보존한다. LLM judge로 사람답을 채우지 않는다. 한 사람만 평가하면 provisional이며2인 검증이 아니다.

수정1회는 후보 확인 후 하나의 수정요청 묶음을 반영하는 라운드다. 클릭수와 다르다. 외부 도구에서 전체 이미지를 다시 제작하면 usable로 세지 않는다.

시간은 난이도를 맞춘 brief 쌍으로 도구 순서를 교차배정한다. 과제별 단축률=(baseline 활성시간-tool 활성시간)/baseline 활성시간, 5개 비율의 중앙값을 사용한다. 모델대기와 전체경과를 별도 공개한다. 사후 실패과제 제외·최고사례 선별 금지. 작은 파일럿의 관찰적 결과이며 일반적 인과 우월성으로 해석하지 않는다.

검색 P@5는 query마다 관련 top5 수/5로 계산하며 결과가 부족해도 분모5다. 20query 평균과 query별 실패를 보존한다. 특징 문구오류·추론불확실성·unknown은 별도 보고한다.

## 테스트 층과 조건

1. Unit: schema/권한/metric/비용/patch/splits. 임시 DB와 주입 clock/RNG, 외부 호출0.
2. Contract: 공급자 요청/응답·401/403/429/refusal/timeout/malformed, mock이 실제 품질을 입증하지 않음.
3. Integration: migration/assets/jobs/budget/권한철회/삭제/복원, 두 DB connection CAS, 중간실패 rollback, 재시작.
4. Browser: 실제 HTTP 서버+별도 worker+Chromium. 공급자만 fake이며 inprocess나 화면 route mock만으로 전체 통과 처리 금지.
5. Visual: 긴 한글·줄바꿈·alpha·폰트 대체·세 비율·390px. 실제 bounds+DOM/scene assertion+screen diff. golden 자동 갱신으로 실패 숨기지 않음.
6. Security: token/Host/Origin/XSS/SVG/SSRF/DNS/path/ZIP/upload/prompt injection/권한·비용 우회·로그. 비운영 fixture만 공격.
7. Performance: synthetic10k asset metadata/30k observations/60scenes, 고정 hardware/OS/deps·cold/warm·20회 이상 측정. p95 산식과 개별값 기록.
8. Live: 승인된 계정·자료·비용으로 소스/AI 파일럿. 일반 PR CI에 keys/paid calls 금지.
9. Human: 실제 루브릭·시간·소유자 승인. 모델 자기평가와 테스트 개수로 대체 금지.

제안 coverage는 신규 순수 계약/안전 경로 branch≥90%, 전체core≥80%. 높은 수치가 정확성을 보장하지 않는다. 기존 검사 삭제/skip/표본 축소로 맞추지 않는다. 필수 테스트 skip·not_run·blocked·waived는 pass가 아니다.

## 증거와 최종 승인

Evidence에는 requirement version, issue/test IDs, release/base SHA, 환경·하드웨어·deps hash, fixture/dataset/schema/model/prompt/metric version, 실제 명령·실행시간·결과·artifact hash·검토자를 저장한다. synthetic/licensed_real/human_annotation/provider_live를 구분한다. 테스트용 fixture 외 상용원본/개인댓글/키는 Git·로그에 넣지 않는다.

CL-059 검사기는 누락·다른SHA·위조hash·skip·synthetic-live 혼동을 차단한다. CL-060은 모든 core 인수 증거와 실제 결과물을 확인한 소유자의 최종 승인이다. gate에 코드가 없으면 실제 검증 보고서로 판정한다. 이전SHA 증거를 재사용하려면 변경영향과 재검증 근거가 필요하다.

필수 조건 하나라도 blocked/fail이면 L2 release 불가. 예외승인은 원래기준 pass가 아니며 새 범위버전으로 표시한다. 태그/Release/배포/공개전환은 별도 허가 후에만 한다.
